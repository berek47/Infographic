First visit

Most optimizations win by removing round-trips entirely: cache DNS, reuse a connection, and avoid repeat data fetches.

The takeaway

Most page-load time is network round-trips, not computation. That is why caching and connection reuse beat simply writing faster code.

The real cost

Latency is round-trips, not CPU. Distance and handshakes set the floor.

Caching wins

A warm cache skips DNS, the TLS handshake, and repeat data fetches.

HTTP/2 and 3

Reusing one connection for many requests cuts the round-trip tax further.

§1The path

A click becomes a sequence: browser, DNS, TCP/TLS, server render, database query, and response bytes. Every leg adds time.

T_total = T_DNS + T_TLS + T_server + T_DB + T_response (1)

On a repeat visit, the formula changes because entire terms can disappear.

§2The useful optimization

Speeding up server code helps, but cutting round-trips is usually more powerful: cache, preconnect, reuse, and avoid refetching unchanged data.
